CLI-Anything: generating a tested CLI for any app so agents skip the GUI

What it is

A coding-agent plugin from the HKU Data Intelligence Lab. You point /cli-anything at an application's source tree or repo, and the agent builds a Python CLI "harness" for it: a Click-based command tree with a --json flag on every command, a REPL mode, tests and a generated SKILL.md. The pitch is that agents drive software more reliably through commands that return structured output than through screenshots and clicks.

There is a community registry (CLI-Hub, pip install cli-anything-hub, then cli-hub install <name>). The README lists harnesses for GIMP, Blender, Inkscape, Audacity, LibreOffice, OBS, Kdenlive, Draw.io, Zoom, ComfyUI, Ollama, QGIS, FreeCAD, RenderDoc and others, plus machine-control harnesses such as a laser cutter (MeerK40t) with safety-gated jog and preflight commands.

Architecture

  • Seven-phase pipeline run by the agent: codebase analysis, architecture design, implementation, test planning, test writing, documentation, then packaging (with SKILL.md generation as phase 6.5).

  • Wrap, don't replace. The CLI writes valid project files (ODF, MLT XML, SVG and so on) and calls the real application to render or process them. Real software is a hard dependency; tests fail rather than skip when the backend is missing.

  • Dual interface. Subcommands for scripting; a bare invocation drops into a stateful REPL with undo and redo, shared across all harnesses.

  • Discovery. Each harness installs as cli-anything-<app> on PATH; agents find it with which and learn it from --help and the SKILL.md, whose content is extracted from the Click decorators.

  • Testing layers. Unit tests on synthetic data, end-to-end tests on real files, "true backend" tests that invoke the app and check outputs (for example PDF magic bytes), and subprocess tests of the installed command. The README reports about 2,460 passing tests across about 30 harnesses.

  • Extra plugin commands to refine coverage with gap analysis, rerun tests, and validate against a HARNESS.md standard.

Why CLIs instead of GUI agents or MCP

  • Determinism and cost. A command with JSON output is cheaper and more repeatable than a vision loop over screenshots.

  • Self-description. --help and a SKILL.md give the agent progressive disclosure, without loading a full tool schema into context.

  • Composability. Shell pipelines and scripts work for free; humans can run the same commands.

  • Versus MCP. A CLI is local and needs no server, but has no built-in authentication, schema negotiation or remote transport. Teams that need remote access or central policy will still put an MCP or API layer in front.

Tradeoffs and failure modes

  • Coverage is whatever the agent understood. A generated harness exposes the slice of the app the analysis found. Silent gaps look like features the app lacks.

  • Drift. When the upstream app changes its file format or internals, generated wrappers break. Pin versions and rerun the true-backend tests on upgrade.

  • Generated tests check generated code. The same agent writes the CLI and its tests, so shared misunderstandings pass. The true-backend layer helps; human review of the test plan helps more.

  • Supply chain. Installing community harnesses from a registry means running third-party code with the app's privileges. Review before install, as with any package.

  • Untrusted input. Harnesses parse project files; the project has already had to harden XML parsing (defusedxml) and token-file path traversal. Expect more of that class of bug.

  • Physical side effects. For machine-control harnesses, the safety gates are the product. Dry-run and preflight must be the default path.

  • Licensing. Wrapping an app does not change its licence; check the wrapped software's terms before redistribution.

Review checklist

  • Does every command support --json with a stable schema, and non-zero exit codes on failure?

  • Do true-backend tests exist for the operations you rely on, and do they fail when the backend is absent?

  • Is the app version pinned and recorded with the harness?

  • Are destructive or physical actions gated behind explicit flags or confirmation?

  • Has a human reviewed the generated SKILL.md for wrong guidance?

  • For a registry harness, who maintains it, and when did it last pass tests?
