Thesis

An LLM is a dependency with no source, no semantic versioning and a retirement date, so the software supply chain playbook applies almost line for line. The running example is a covenant-monitoring pipeline that pulls EBITDA and net debt from quarterly reports. Evidence for drift under a stable name includes GPT-4's prime-number accuracy falling from 84% to 51% between March and June 2023, and Thinking Machines getting 80 distinct completions from 1,000 temperature-zero runs (batch-invariant kernels made them identical at about 1.6x runtime).

Six habits

  1. Pin the closure, not the name. Direct dependencies are the prompt, output schema, tools, retrieval index and model; transitive ones are the embedding model, serving stack and region. The example ai-lock.yaml holds a dated snapshot ID, region, temperature and token limits, SHA-256s of prompt and schema, hashes of each tool definition (name, description, inputSchema, to catch an MCP "rug pull"), the embedding model and index snapshot, a gold-set reference with runs_per_item: 5, and a fallback pinned to a hub commit. verify_lock() runs in CI, at startup and on MCP tool listing, and fails when a pinned model retires within 90 days. Only 21.9% of 1,262 prompt changes across 243 repos were documented in commit messages.

  2. Test upgrades statistically. An item passes if it is right in at least 4 of 5 runs. Compare old and new with a paired exact binomial (McNemar-style) test on the items where they disagree: 40 fixes and 12 regressions does not reject but lists the 12 for review; 10 fixes and 30 regressions rejects. Then shadow, canary with human review, promote, and run a daily drift probe on the pinned model into a control chart.

  3. Keep an AI bill of materials. A CycloneDX 1.7 AI-BOM generated from the lockfile in CI, with a who_uses() query for the Log4Shell moment. Tied to DORA's third-party register and EU AI Act Art. 53.

  4. Debloat the agent. Tool definitions are context: five MCP servers with 58 tools cost about 55,000 tokens before the conversation started; tool search cut that 85% and raised one model's MCP eval accuracy from 49% to 74%. Log production tool calls and delete tools that are never called.

  5. Verify what you load. Pull weights by commit SHA, never main; allow only safetensors and JSON; check the exact file set and digests; mirror internally; sign models where possible. Cited threats: slopsquatting (19.7% of 576,000 generated package references did not exist), abandoned Hugging Face namespaces, pickle payloads, and poisoning with as few as 250 documents.

  6. Plan the exit. Anthropic commits to at least 60 days' notice before retiring a public model; OpenAI announced on 11 June 2026 that GPT-5 and o3 snapshots shut down on 11 December 2026. Switching cost rises from prompt (rerun the gate) to model snapshot (rerun, recheck calibration) to tool server to embedding model (re-embed the corpus, rebuild the index), the stickiest.

Engineering takeaways

  • The lockfile plus statistical gate is a concrete, adoptable pattern; the 4-of-5 rule and the paired test on disagreements are the useful details.

  • Hashing tool definitions closes a gap most MCP clients leave open: a server can change a tool's description under you.

  • Embedding models are the hardest dependency to swap; pin them hardest.

Caveats

The cited numbers are the author's and unverified here. The regulatory framing is EU and US banking-specific.
