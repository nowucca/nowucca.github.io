Source: FastMCP documentation, "Skills over MCP" (PrefectHQ/fastmcp, docs/servers/skills.mdx, version 4.2.0), Apache-2.0. Surfaced by André Lindenberg.

The problem

A skill is a SKILL.md of instructions plus the files it references. Most agents load skills from a local folder, so every laptop has its own copy. When an MCP server's tools change, the skill that explains them goes stale on every machine until someone updates it.

What 4.2 adds

  • Skills as server resources. A SkillCatalogProvider serves skills; any client can read skill://<name>/SKILL.md and its files as ordinary MCP resources. Deploying the server ships tools and the instructions for them together.

  • Skills extension support (experimental). Clients that implement the MCP Skills extension can call skills/list and receive each skill's description plus a hashed manifest of its files, so a host can offer a skill without an install step. Few hosts support this yet.

  • Sources. Skills can be built in Python, loaded from a directory or package, or produced per request from a database by overriding load_skills(). A SkillManifestProvider serves large skills from object storage by digest without holding them in memory.

  • Client-side install. For agents that only read local folders, the FastMCP client can list and read skills and write them to a directory, so a post-deploy step can refresh local copies.

Design notes

  • Skills are immutable values once built; editing a folder later does not change a loaded skill, which makes what is served reproducible.

  • The description is what an agent reads to decide whether to use a skill, so it should say when to use it.

Tradeoffs

  • Central serving fixes drift but adds a dependency: no server, no skill.

  • Serving instructions from a server is also an injection surface; only trust skill servers you control.

  • Per-request generation from a database makes skills dynamic, which is powerful and harder to review.

Review checklist

  1. Where do our agents' skills live, and how many divergent copies exist?

  2. Do tool changes and their skill text ship in the same deploy?

  3. Who can publish to the skill server, and is content reviewed?

  4. Can clients pin a skill version by digest?
