Source: Why I'm Bullish on MCP for 2027, Philipp Schmid, 26 Nov 2026. Found via TLDR AI and TLDR Dev 2026-11-27. Diagrams and linked sources are outside the scope of this summary, so usage numbers are the author's citations.

Adoption numbers cited

  • Linear and Notion: agents create roughly half of all issues (about 2.4M a week) and pages; Notion reports 60x MCP traffic growth.

  • Atlassian: over 5M MCP tool calls per workday, 44% from users outside software teams.

  • Neon: agent usage over MCP growing 14% week over week.

  • Apple ships local MCP servers for Pages, Numbers and Keynote.

What changed in the protocol

The 2026-07-28 spec dropped stateful sessions and added official extensions:

  • Code Mode. Instead of loading many tool schemas into the prompt and calling one per turn, the harness exposes MCP tools as typed functions in a sandbox. The model writes one script that chains calls, filters and joins in memory, and returns only the result (the example joins a Linear issue list with per-issue Sentry lookups). It depends on servers declaring outputSchema alongside inputSchema. The author says it is already the default in OpenCode 2.0, Claude Code, Codex, Pi and Factory Droid. Auth stays outside the sandbox as per-user OAuth 2.1.

  • Skills (io.modelcontextprotocol/skills, SEP-2640). Each skill has a skill:// URI, frontmatter and a file manifest with SHA-256 digests. On connect the harness lists only names and descriptions and loads the full SKILL.md on demand; digests let clients cache and pick up vendor updates.

  • Events (io.modelcontextprotocol/events, beta). Webhook, push stream or poll delivery, with a client cursor and dedup by eventId; the harness can wake the agent into the same or a new trajectory (for example a Vercel deployment.succeeded).

  • Tasks (io.modelcontextprotocol/tasks). Combined with Events, async work needs no custom webhook glue. He proposes subagents as MCP Tasks with a shared board and Events waking the coordinator.

  • Apps (io.modelcontextprotocol/ui). Servers return sandboxed interactive HTML views.

Gaps he names

  • Intent: servers see tool calls, not the conversation; "most servers still don't know why they were called." Proposed: telemetry.intent metadata and feedback tools.

  • Discovery: registering with five registries doesn't scale; he proposes a /.well-known endpoint with automated security scanning.

  • Security: webhook payloads, Code Mode sandboxes and embedded UI iframes all widen the prompt-injection surface.

His design rule: "Good MCP servers expose tools for agents, not agents as tools."

Engineering takeaways

  • Declaring outputSchema is now what makes a server cheap to use, because Code Mode clients can chain it without round-tripping results through the model.

  • Skills over MCP turn a server into a versioned distribution channel for instructions, with digests as the update mechanism.

  • Events plus Tasks are the missing pieces for long-running multi-agent work over a standard protocol.
