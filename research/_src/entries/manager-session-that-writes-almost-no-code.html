The setup

The main Claude Code session is a manager defined by one 129-line skill file. It plans, briefs separate Claude Code agents, checks their output, merges and ships. Each feature gets its own agent in its own git worktree; items that might conflict run in sequence, the rest in parallel. Agents are started and messaged through Herdr's hc CLI (hc --skill prints the manual the manager reads).

Per-feature pipeline:

  1. The agent writes a plan; the human approves it.

  2. It builds with tests and a simulator video as proof, committing each logical chunk.

  3. It self-reviews with /code-review, and a GPT model reviews the diff as a second opinion.

  4. It reproduces each finding before fixing the real ones.

  5. The manager checks commits, tests, the video and a Release build itself ("doesn't trust a 'done'"), merges and ships a TestFlight beta. A failed beta blocks the queue.

Numbers (one developer, one iOS app)

  • 37 TestFlight betas in five days (builds 12 to 48), against 9 in the previous five.

  • The manager started 84 agents, which sent it 303 messages.

  • Of the manager's 2,057 tool calls, 44 were file edits, about 2%, against 11% in his other sessions.

Why separate agents rather than subagents

For hour-long work, a full session can run its own review, the human can type into any agent's terminal, the manager's context stays small, and agents survive manager restarts or compaction. The cost is plumbing: terminals, messaging and worktree cleanup.

Failure modes he hit

  • Agents stalled on permission prompts nobody watched, so all agents now run in auto mode.

  • An approval relayed by the manager doesn't count as human consent when auto mode blocks something; the fix is Remote Control on that terminal.

  • Three features merged without a beta; one 35-finding sync feature ran a whole day.

  • hc send doesn't run slash commands (hc keys does); the manager may clean up only agents it started; and the manager has occasionally fixed a Release build or test itself.

Engineering takeaways

  • The manager's value is verification it does itself: Release build plus recorded proof, not the worker's report.

  • Plan approval is the one human gate; everything else is automated checks.

  • Measuring the manager's edit ratio (2%) is a simple way to tell whether it is managing or coding.

Caveats

Self-reported, one app, no controlled comparison beyond the prior five days.
