Sources: Kumar, Meincke, Shapiro, L. Mollick, Puntoni and E. Mollick, "Prompting Science Report 6: Agentic Shopping is Complicated and Contingent", Wharton Generative AI Labs, 2026-08-27, https://gail.wharton.upenn.edu/research-and-insights/technical-report-agentic-shopping/ (SSRN 7355899); resurfaced by Ethan Mollick on 2026-11-23, https://lnkd.in/p/gTncDFJY

TL;DR

Across roughly 26,000 trials, six frontier models acting as shopping agents made stable, model-specific choices when shown only a product grid. Adding realistic context (one review-site screenshot, several competing sources, a change in source order, a one-line injected user "memory", or even bundling vs splitting tool results) shifted choices, sometimes by nearly 100 percentage points. The more context was added, the less predictable the choice. Models differed sharply, even within a family. The practical lesson for anyone building or evaluating agents that act on retrieved content: clean-page benchmarks overstate stability, and the composition and delivery of context is part of the decision function.

Setup

  • Task: personal shopping assistant choosing a fitness watch for a user with no stated requirements, in the ACES agentic e-commerce simulator.

  • Inputs were screenshots: an eight-product grid, plus, by condition, screenshots of prior sources. Three sources each favored a different product (a Reddit thread, Wirecutter, The Strategist).

  • Models: Claude Haiku 4.5, Claude Opus 4.8, GPT-5 Mini, GPT-5.5, Gemini 3.1 Flash Lite, Gemini 3.5 Flash; 200 runs per condition at temperature 1.0. The tool-call study used four models and no Anthropic models.

  • Five manipulations, layered one at a time: single source, multiple sources, source order, injected user memory, bundled vs separate tool calls.

Findings

  • Each model has a default. On the bare grid, each settled on a stable favorite, and favorites differed across models.

  • One source can override it. A single source screenshot often flipped the choice; Gemini 3.5 Flash followed one review site's pick in essentially every run (+99 pp). GPT-5 Mini barely moved.

  • Sources don't average. With conflicting sources, one source won outright and which one depended on the model. One source dominated broadly; the only pairing that excluded it moved no model.

  • Order matters for some models. Same three sources, shuffled: some models were order-invariant, but Gemini 3.1 Flash Lite's choice depended on which source came first.

  • Injected memory redirects even when one product is objectively best. With a $29.99 perfect-rated option against $359+ alternatives, a single planted sentence ("I love hiking!") pulled most models toward a hiking-oriented watch; Claude Opus 4.8 switched in about three-quarters of runs. GPT-5 Mini responded only to the negative version. Only Gemini 3.5 Flash both picked the best product at baseline and held it under every injection.

  • Tool-call packaging changes outcomes. Delivering the three sources in one bundled tool result vs three separate results changed choices; GPT-5.5 moved +53 pp when bundled and barely at all when split.

Why it matters beyond shopping

  • Context is an input to the decision, not neutral background. Any agent that ranks, selects or recommends from retrieved material (vendor choice, library selection, ticket triage, code-review prioritization) inherits these sensitivities.

  • Memory is an attack surface. A persistent user-memory store that a third party can write to, directly or by getting content summarized into it, can steer downstream actions. Treat memory writes as privileged.

  • Harness design leaks into behavior. Whether results arrive bundled or split, and in what order, are engineering choices that change outcomes. They should be fixed, documented and tested, not left to incidental implementation.

  • Per-model calibration is required. Susceptibility patterns do not transfer across models or even across sizes in one family, so switching models invalidates robustness results.

Limitations

  • One product category, one simulated storefront, screenshots as the only modality, and a user with no stated requirements (which maximizes room for context to matter).

  • Temperature 1.0 inflates run-to-run variance relative to many production settings.

  • Anthropic models were absent from the tool-call study.

  • The report shows choice shifts, not whether shifted choices were worse for the user, except in the memory study where an objectively best option existed.

Checklist for teams shipping decision-making agents

  1. Do your evals include realistic and adversarial prior context, not just the clean decision page?

  2. Do you test permutations of source order and tool-result packaging, and fix them in the harness?

  3. Who can write to agent memory, and are memory-derived preferences shown to the user before they drive an action?

  4. When an objectively better option exists, does the agent find it under noisy context? Measure that directly.

  5. Are robustness results re-run on every model change?

  6. Do you log which sources the agent saw, in order, for each decision so you can audit steering?
