Bas Nijholt runs 15 parallel coding sessions on a normal day and up to 40 at peak. Each task is a chat thread: the thread is the agent's context window, and each one gets its own git worktree, a parent orchestrator agent, and cross-model review (nijho.lt, 23 Nov 2026). He reports about 4 million lines changed in the first 20 days of November and $50,000 to $100,000 a month in model spend. He says the hard limit is now his own working memory, not the agents. He co-founded MindRoom, the tool he describes, and its chat client is open source (mindroom-chat, Apache-2.0).

Architecture

  • Thread = task = context. A room is a list of tasks. A thread is compacted when it fills, and agents can read other threads with tools.

  • Isolation. Each coding thread gets a git worktree, with its PRs linked to the thread. One meta-repo checkout holds every repository, and the agent infers which one from context.

  • Parent and sub-agents. A parent agent on Opus 5.5 holds skills, memories, review standards and git workflow. It delegates edits and reviews to sub-agents in a minimal mode with a short system prompt.

  • Model routing.

No model reviews its own code, and after a fix round a fresh reviewer re-reads the whole diff. On ambiguous design choices, a cross-model consultation skill has one lab's model ask another's. Nijholt is asked only when they disagree.

The status view

Threads sort into four sections: Needs you (finished or asking, nothing running), Working (replying, or a sub-agent or background job is running), Later (snoozed or scheduled) and Done. Each card has three lines: an AI title, the current activity or the start of the last answer, and the participants, PR and tags. Status comes from activity, so a thread with a background job doesn't look idle. He moved off T3 Code because past about 20 sessions its single-threaded database writes made threads slow to open and misreported idle ones.

Numbers worth noting

  • A linked study of more than 4,000 runs found that a minimal agent (one shell tool, a 12-line prompt) used 58% to 76% fewer tokens than MindRoom's standard agent.

  • A test-first skill made the agent write a failing test before the fix in 32 of 32 runs, against 0 of 32 without it.

  • Merged output from Nov 2025 to Oct 2026 was about 10 million lines in 5,148 PRs, against 1.4 million the year before. The jump coincides with GPT-6 Astra and Opus 5.5 in September 2026. He says the chart measures work in flight, not quality.

Tradeoffs and failure modes

  • He no longer reads code line by line. He checks diff size and asks the agent targeted questions about trade-offs, so quality rests on the cross-model review.

  • Cost is the biggest risk he names.

  • He says earlier guardrail hooks now barely matter. That is one person's experience, not evidence about safety.

  • Rigid pipelines lose to letting the orchestrator decide; skills (spec, plan, test-first) carry the discipline instead.

Review checklist for a multi-thread setup

  • One task per isolated worktree, with PRs linked back to the thread.

  • Reviewers from a different lab than the author model, plus a fresh re-review after fixes.

  • Status derived from activity, including background jobs.

  • Behavioural skills measured (like the 32 of 32 test-first result), not assumed.

  • Spend tracked per thread.
