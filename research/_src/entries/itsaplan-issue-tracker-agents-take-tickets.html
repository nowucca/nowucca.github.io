What it is

A self-hosted project tracker (Kanban, timeline, cycles, docs), pitched as an open-source Linear alternative. AI agents are project members you can assign issues to, the same way as people.

How agents work in it

  • Internal agents run on the server with any model and API key, built on Mastra.

  • External agents run on your own machine through @itsaplan/runner, using your own Claude Code, Codex, Copilot CLI or opencode account. The server hands out work; your machine does it with your credentials.

  • Triggers: an @mention, an assignment, or a schedule starts a run.

  • Integration: a REST API with OpenAPI, an MCP server, webhooks, and PR integration with five code forges.

Stack and license

Bun and Turborepo, Elysia backend, Next.js frontend, better-auth, Drizzle on PostgreSQL. AGPL-3.0, except the runner package, which is Apache-2.0 so it can run inside companies without AGPL obligations. A paid Pro tier is a flat $240 a year per instance.

Why it matters for a staff engineer

This is the issue tracker as the agent control plane: the ticket is the unit of work, assignment is dispatch, and the comment thread is the log. The split between a central server and a local runner that uses the developer's own agent subscription is a pattern worth noting. It keeps credentials and compute on the developer's machine and avoids the server paying for model calls. Compare R262 and R273, which put the control plane in a session manager or chat room instead of a tracker. There are no reliability or throughput numbers; judge it as a design, not as evidence.
