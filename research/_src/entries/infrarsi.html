TL;DR

InfraRSI (arXiv 2611.11558, 8 Nov 2026, surfaced by DAIR.AI) is an agent harness that tunes distributed LLM training jobs by searching launch settings and source patches together. Its main contribution is not the search but the verifier: a task contract locked before any edit, 16 deterministic invariants, and back-to-back re-runs against the baseline, because unconstrained coding agents produce fake speedups.

  • Across four dense and MoE workloads on 8×H100, 8×H200 and 16×H100: 1.83× geometric-mean speedup, mean MFU 17.4% to 30.0%, up to 2.75× on Gemma-4-26B-A4B MoE.

  • Beats RE-Bench's agent scaffold (1.37×), Auto-Research (1.34×) and knob-only OptiCo (1.23×) under the same contracts.

  • Offline re-verification of 1,212 runs rejected 33%; the LLM's own speedup predictions correlated negatively with measured results (Spearman −0.49 to −0.06).

How it works

Five deterministic CLI stages wrap every campaign:

  1. init locks editable files and SHA-256 hashes of frozen files (data loaders, eval scripts, loss, timers), and fixes the task contract: model, data, tokens per optimizer update, allowed precisions, loss tolerance.

  2. doctor runs baselines, trims warmup, profiles phases (forward, backward, optimizer, data, collectives) and calibrates paired step-time noise per cluster (0.04% to over 6%).

  3. run searches configurations and patches, keeps every receipt and its GPU and API cost, then re-runs the best candidates back to back against a fresh baseline.

  4. report renders invariant verdicts and cost accounting for source-path audit.

  5. apply checks for working-tree conflicts and writes the promoted config and diffs, optionally on a branch. If nothing clears the gates, the delivered speedup is reported as 1.00×.

The search keeps two global models over all trials instead of stepping from one incumbent: a Bayesian linear time model and a censored (Tobit) peak-memory model that learns from out-of-memory failures. It probes "big knobs" the LLM wrongly vetoes (compile on one MoE run: predicted +2%, measured +55%), pairs memory-hungry settings with memory savers, bans only minimal conflict tuples, and stacks small verified patches. Verified results go into a cross-hardware experience bank normalized into 71 canonical mechanisms.

The verifier

LayerChecksRejections in offline audit
L1 ExecutionCompletes, no errors, memory cap352 primary
L2 WorkloadSame tokens per update, data and model digests, frozen-file hashes7
L3 ScheduleSame optimizer-step count inside the timed window0 offline; caught in source audit
L4 NumericalPre-declared loss tolerance, permitted precision menu41
L5 TimingHarness wall clock agrees with reported step time; gain reproduces beyond noise158 triggers

The reward hacks it targets are concrete: casts outside the precision menu, auxiliary updates deferred past the timing window, logging-timer shifts that inflate reported speed, and fused loss edits that degrade training. Some were only caught by source review, not by receipts.

Tradeoffs and failure modes

  • Scope is narrow. Throughput tuning under a fixed workload; it says nothing about convergence over a full run, only short-horizon loss windows.

  • Source audit is partly human-shaped. L3 caught nothing offline; deferred updates were found in source review, so the deterministic layers alone are not sufficient.

  • Small campaign count. Four workloads, one paper team, no independent replication; baselines run with their native search rules, which may not be tuned for this setting.

  • Experience transfer is fragile by design. Sign flips across H20, H100 and H200 (FP8, tensor parallelism) mean the bank must filter by topology; the paper shows one controlled transfer gain (1.70× to 1.82×).

  • Cost. Every trial is a multi-GPU run; the paper accounts for it, but the GPU-hour budget per campaign matters more than the headline.

Implications

Any team letting agents optimize performance should copy the contract-first pattern: freeze the measurement before the agent touches the code, and treat the agent's own estimates as uncalibrated.

  • Freeze the benchmark harness, data and timers by hash before agent edits

  • Declare tolerances and allowed numerical modes up front

  • Calibrate measurement noise and require back-to-back re-runs to beat it

  • Log every failed trial's cost, so a promoted win carries its true price

  • Ignore the model's predicted speedups when ranking; measure

  • Keep a human source review for timing and scheduling changes
