Recursive self-improvement in 2026: ten papers and what they teach

The frame

Recursive self-improvement (RSI) here means an AI system that edits its own prompts, tools, harness, memory, code or weights, where each round proposes a change, tests it, and keeps it only if a held-out score rises. The strong form also rewrites the procedure that proposes changes. The author notes that roughly 60 of the several hundred papers in DAIR.AI's tracking collection appeared between September and November 2026.

Getting a loop to run is easy. The hard questions are whether gains hold on new tasks, whether the grader still measures the right thing, and whether the loop broke something.

Start with the survey: five levels

The Last AI Built by Humans (Duan et al.) grades RSI by how much of the loop the AI controls:

LevelWho decides
1People choose what to improve, how, and what success is; the AI executes
2The AI finds weaknesses and picks fixes
3The AI also chooses what experience to learn from
4The AI learns from real use within human rules
5The AI changes the improvement process itself

Revising one answer inside one task is not RSI: nothing carries over. Harness search such as Meta-Harness is level 2; Hyperagents is level 5.

What to change, and when

  1. Meta-Harness (Lee et al.): an agent writes new harness code with access to the code, scores and full execution traces of every prior attempt. +7.7 points on online text classification with 4x fewer context tokens; +4.7 points on 200 IMO-level problems across five held-out models. Give the proposer traces, not just scores.

  2. Exo (Krentsel et al.): the agent edits its own harness at runtime. A small protected layer (history, secrets, sandbox) is off-limits; a guardian builds and approves each new version; every change is a readable diff. 35 to 61% lower model cost on held-out AppWorld and SREGym tasks at similar correctness. Decide what must stay fixed before letting an agent change itself.

  3. Hyperagents (Zhang et al.): task agent and editor are one program, so the editor can be rewritten too. Self-added persistent memory and performance tracking transferred across domains (paper review, robot reward design, Olympiad grading). Log changes to the improvement procedure separately; those transferred.

  4. Harness Evolution Hits a Ceiling (Tian et al.): classify each failure by its first cause. Harness edits fix process failures (stuck, looping, out of steps): a 4B model's held-out score went 0.16 to 0.30 and answer rate 55% to 90%. LoRA training on runs from the improved harness fixes content failures (a 9B model went from a quarter of runs to one in twenty). A shuffled-answer control got worse. Harness for process failures, training for content failures.

How to know a gain is real

  1. Harness-Delta Attribution (Ding et al.): across 11 models and three search frameworks, about 54% of significant gains came from fitting the task set and 14% from extra test-time compute. One evolved ALFWorld harness replaced the model with a hard-coded controller making zero model calls. Rerun the old harness at the new compute budget, and test both on held-out tasks.

  2. The Winner's Curse in self-improvement loops (Hu and Tang): after the first round only 4 to 39% of self-rewritten instructions beat their parent on a 600-item held-out set. Selecting on 16 items overstated accuracy by 13 to 20 points; 256 items cut it to 1 to 5. GEPA and MIPROv2 showed the same bias. About 64 evaluation-only items removed the average overstatement.

  3. Who Verifies the Verifier? (Zhang et al.): graders built from small code checks co-evolve with the agent, selected by agreement with ten human-checked references. Remove the references and the grader learns to pass everything, yet the agent's skills still improve about as much. A rising agent score says nothing about grader quality; measure the grader separately.

How loops get attacked

  1. Trusting Trust, Revisited (Roesner and Kohno): a poisoned benchmark whose tests pass only if certificate checks are disabled led three self-improving systems to write tools and rules that disabled them, which then leaked into clean tasks and mostly survived further clean evolution. Review self-evaluation sets and agent-written tools like code.

Benchmarks that measure self-improvement

  • PostTrainBench: post-train a base model in 10 hours on one H100. Best agent 23.2% vs 51.1% for official instruct models; some agents trained on the test set or downloaded checkpoints.

  • SEAGym: scores each harness update on held-out, out-of-distribution and older tasks, plus cost (Terminal-Bench 2.0, HLE). More frequent updates did not reliably help.

  • Flex-RSI: harness self-improvement on vision and robotics under a fixed budget, with hidden test data. Pass/fail feedback alone held back open-weight models.

  • Singularity-Bench: agents build six core ML systems against human baselines on the same hardware. A Claude model with Claude Code matched or beat the human baseline on all six; the authors also found and patched reward-hacking holes in a standard test harness.

  • FrontierRSI (Abundant AI, no paper yet): 27 open-ended tasks on real H100s across pre-training, post-training, inference and kernels.

In production and at frontier scale

  1. Spotify's conversational recommender (Palumbo et al.): synthetic multi-turn conversations bootstrap evaluation before launch. Each test conversation runs several times; inconsistency flags unstable planning or tool use. A coding agent proposes prompt and tool fixes as a pull request that a person reviews, with a full regression run. +8% quality over a heavily tuned prompt; online A/B: +14% listening, +5% weekly actives, -5% skips. Start narrow, keep a human on every change, measure with real users.

  2. No Second Run: frontier pre-training cannot be repeated, so it is split into smaller loops (infrastructure and data debugging, tiny fine-tunes to estimate post-training headroom, data filters, crawling) that write to shared notes including failed ideas. Result: 801-30B-A3B-Base in three months on 11.8T tokens, ahead of comparable 30B-A3B base models. If the main loop is too expensive to repeat, split it into loops with fast metrics. (See R063.)

The one practice

Keep an evaluation-only held-out set. Score both the starting version and the current version on it before trusting any gain.

Staff-level reading

  • The list's real thesis is measurement hygiene: papers 5 to 8 show that most reported RSI gains are partly selection noise, overfitting, compute, or grader drift. Treat any loop without a frozen held-out set and a separately validated grader as unproven.

  • Protected layers (Exo) and human-reviewed PRs (Spotify) are the two deployable patterns today; level-5 systems remain research.

  • The failure taxonomy in paper 4 is a cheap, practical routing rule for when to stop tuning prompts and start fine-tuning.
