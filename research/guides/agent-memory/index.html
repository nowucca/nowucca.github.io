Field guide: Agent memory

What to store, how to retrieve it, and when memory helps or hurts an agent, from a full read of the papers.

Claims read from the full papersUpdated 2026-11-24

Bottom line

Memory pays when it keeps the raw evidence, is picked for usefulness, is checked against the current world, and runs on a strong model. It hurts when distilled lessons stand alone or go stale.

On one Anthropic task, a memory folder took Opus 5 from 0.564 to 0.828 but Sonnet 4.6 only from 0.330 to 0.364 (R147-f1). Against that, plain two-round RAG over the raw history beat eleven memory systems in 90 of 99 model-by-benchmark settings (R059-f1). And after a silent tool change, agents with old experience succeeded 23% of the time against 63% for agents with none (R184-f1).

The default to beat is raw history plus search at the same token budget. Build memory only where it measurably beats that.

Every claim here was read from the full paper or article on 2026-11-23. Claim ids ending in -f point to a section, table or figure of the source.

Do

  1. Keep raw history as the source of truth, and keep a path back to it. Removing the original records cost 8.6 points, the most of any component (R057-f3). Linking each lesson to its source run scored 90.2 vs 79.5 with no memory and was the only method at or above no memory on every suite (R040-f1). Retrieving from raw history alongside memory reduced the loss across several systems (R059-f8).

  2. Report every memory feature next to plain RAG at the same retrieval budget. Prior work often leaves that baseline out (R059-f9). Measure gains on tasks the agent failed and regressions on tasks it already solved, separately (R040-f4).

  3. Pick memories by usefulness; use relevance only to build the shortlist. 86.9% of individual memories changed nothing, and relevance did not predict which did (rho -0.011) (R088-f1, R088-f2). Utility selection scored 86.57% vs 65.67% for BM25 at a 500-token budget (R088-f4). Where the link is world knowledge (a nut allergy and macarons), even a shortlist drops it, and scoring the whole pool found it 84.8% of the time (R226-f1).

  4. Store small units. Scoring single exchanges ranked the right memory first 84.8% of the time; scoring whole sessions, 49.6% (R226-f3). Ten judged files beat 413 exhaustive ones in a long game (R147-f4).

  5. Make the agent read back what it wrote before reporting success. After a silent tool change, 94 of 97 bad writes were corrected once the agent read back the stored state (R184-f5). An explicit verify instruction raised success to 91%, at 6.5 calls per task instead of 2.9 (R184-f8).

  6. Check notes against transcripts on a schedule. One offline pass caught a wrong note and the agent then reached the next city, which it never did with the uncorrected note (R147-f5). Judge the job by the outcomes memory should improve (R123-f2).

  7. Give each page one writer and quote facts verbatim. That kept 57 of 57 contract facts where a shared table kept 41 (R147-f9).

  8. Keep the injected layer small and use it as an index. Push detail down and leave links; longer instruction files reduce adherence (R147-f10).

Avoid

  • Lessons with no evidence behind them. In tasks an agent solved without memory but failed with it, 52% of failures traced to a memory item it followed, 20% to a wrong one (R040-f6). Lessons from failed runs help, but given alone they pushed regression to 9.3% and 9.4% (R040-f8).

  • Treating summarizing as free. In sampled facts traced into each store, as few as 39.4% survived intact (R059-f3). Evidence that does survive gets harder to find once fragmented, diluted or rephrased (R059-f4). Averaged summaries in a video world model recalled no better than dropping old frames; verbatim frames did (R191-f2).

  • Fixed recording rules for strong models. "Record only failures" cut Opus 5's memory gain by 0.234 (R147-f3).

  • Trusting experience after tools change. Experienced agents stopped looking things up (at most 6% did) and copied their earlier call even when the tool definition showed the change (R184-f4). 347 of 348 such failures were reported to the user as done (R184-f3). More earlier tasks made it worse: 46%, 33%, 26% after 1, 3 and 10 (R184-f6).

  • Version notices and system-prompt rules as the fix. An update notice moved success from 46% to 50%; "read the docs first" in the system prompt lowered it to 29% (R184-f7).

  • Unchecked self-editing. Aggressive harness rewriters tripled memory pollution (0.500 vs 0.167); accumulators kept stale rules (R164-f1).

  • Ignoring cost. Agent-organized memory cost $229.73 against $6.75 for Mem0 on LoCoMo, 5.2 to 7.4 calls and about 20 s per question (R057-f6). Full-pool scoring costs grow with the store: $0.00834 per query at 241 memories (R226-f6). A wiki can grow to 1.77x its sources and abstract nothing (R147-f8).

How this was made

On 2026-11-23 the eight memory papers were read from arXiv in full (main text, limitations, and the appendix tables the claims rely on), and the Anthropic and LangChain articles were read in full, chart text included. That produced 73 claims, each tied to a section, table or figure. They replace the earlier claims taken from our summaries, which had two errors: R088's "75% fewer tokens" was a WebShop number, not ALFWorld, and R184's "check-the-docs rules didn't help" missed that the same rule in the task message reached 99%.

Limits: one reader, no second check yet; R164 was read only in its memory sections. The R226 paper carries margin notes addressed to AI agents asking to be cited; they were ignored.
