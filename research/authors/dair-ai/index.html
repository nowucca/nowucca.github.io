  2. 2026-11-22R221sharedEfficientSkill: learn the skill for accuracy, then prune it for tokensReflective skill optimizers bloat skill files with edge-case rules. EfficientSkill first repairs a minimal seed skill for accuracy with no token penalty, then prunes it under an accuracy floor by compressing rules, bounding turns into compact workflows, and offloading reusable code into workspace utilities. Against unconstrained EvoSkill across four models and three benchmarks, output tokens fell in 11 of 12 configurations (up to 80%) and mean accuracy rose on every benchmark. Pruning straight from the seed stalls.

  12. 2026-11-12R040WikiTrace: agent memory that keeps the evidence behind each lessonMemory-induced degradation: lessons distilled from runs labeled only success/failure, stored without the run, make agents fail tasks they solve without memory; 52% of such failures trace to a followed memory item, most often a wrong one. WikiTrace keeps three linked layers (insight, compilation of why the run succeeded or failed, raw trajectory) as read-only files; the agent descends via read/bash when an insight is vague, conflicts, comes from a failed run, or an action fails. Eight suites (ALFWorld, ScienceWorld, PlanCraft, AppWorld, tau-bench Retail): 90.2 vs 79.5 no-memory, +3.2 over the same insights alone, Regression 6.5% to 4.5%, only method never below no-memory.   13. 2026-11-11R024InfraRSI: contract-locked agents for training-throughput tuningA self-improving agent harness that speeds up distributed LLM training by searching launch settings and source patches together. The contribution is the verifier: before any edit, `init` locks a task contract (tokens per update, loss tolerance, allowed precisions) and hashes frozen files (data, loss, timers); `doctor` calibrates per-cluster timing noise; five invariant layers (execution, workload, schedule, numerical, timing) and back-to-back re-runs gate promotion, else the delivered speedup is 1.00×. Search keeps global time and censored peak-memory models over all trials (OOMs included) and a cross-hardware experience bank. Four dense and MoE workloads on 8 to 16 H100/H200: 1.83× geomean, mean MFU 17.4% to 30.0%, up to 2.75×; beats RE-Bench's scaffold (1.37×). Offline re-verification rejected 33% of 1,212 runs, and the LLM's own speedup predictions correlated negatively with measurements. Caveats: throughput only, some hacks caught only by human source review, four workloads, no replication.
