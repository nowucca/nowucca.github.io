  1. 2026-11-25R293Would a person need to read the papers? Routing and the citation gate in a verifiable research agentA system design for an agent that answers research-and-development questions so that <strong>a reviewer can check every claim</strong>, collapsing the naive five-part build — scholarly search API, PDF parser, domain database, a model to read and write, and the glue between them — into two paths and one gate. The router asks a single question of each request: would a person need to read the papers? No goes to a cheap, high-volume retrieval call that fits inside an agent's inner loop; yes goes to a minutes-long deep-work call that plans, reads the papers and the user's own files, and returns a cited answer. That one question is a cost router, a latency router and a capability router at once, and its failure directions differ in kind: under-routing produces a confident answer assembled from abstracts, which is wrong in a way that looks fine, while over-routing is merely expensive. The gate is the part worth owning rather than delegating: every claim must resolve to a source before it reaches the user, resolution is checked against the cited span rather than asserted, and a claim that does not resolve is reinjected for another pass rather than labelled and shipped — shipping it transfers the work to the reviewer whose time the whole system exists to protect. The granularity of "a claim" is the honest cost nobody wants to pay, since a sentence can hold a supported fact and an unsupported inference. The weakest part of the original is "five parts become two calls": consolidating onto one provider relocates the complexity to a layer you cannot inspect or swap, inheriting its ranking biases, citation-resolution false positives, coverage boundaries and pricing, and it stops being the right trade where retrieval quality becomes the product — which in a verifiable-research product it nearly is. Key caveat: the post's vendor-specific claims do not match that vendor's published introduction and pricing pages, which name no such two products, list none of the claimed patent, clinical-trial, grant or chemical-database coverage, mention no streaming, and price a standard search about an order of magnitude higher — enough to invert the routing economics the design rests on. The architecture survives that check; the specifics do not.

  2. 2026-11-24R288Who writes the citation decides what your reviewer is checkingA document assistant that shows a link under each answer looks finished, but the link's value depends entirely on which component produced it, and teams rarely know. If the retriever emits the reference, a human reviewer is checking evidence: does this passage support this sentence? If the model wrote it in the same pass as the prose, the reviewer is checking a claim against another claim — is the link real, does the passage exist in this version, does it say what the sentence says — and that is a second review step somebody has to own. The 2023 audit it leans on measured four generative search engines at 74.5% mean citation precision and 51.5% recall, so about a quarter of citations did not support their sentence and about half of sentences were not fully supported. Supported statements were largely extractive, so failures concentrate on answers that aggregate across sources. Key caveats: the inverse correlation between grounding and perceived usefulness rests on four systems, the authors call it an empirical observation rather than a fundamental relationship, and it is a snapshot of consumer products from early 2023.

  3. 2026-11-24R277Seven repos as a learning path from autograd to a chat modelSeven Karpathy repositories treated as an ordered curriculum rather than a reading list: micrograd (scalar autograd in ~100 lines), nn-zero-to-hero, minbpe (byte-pair encoding that reproduces GPT-4's token IDs), nanoGPT, llm.c (GPT-2 in plain C and CUDA), nanochat (a GPT-2-class chat model for roughly $48 on eight H100s for about two hours) and autoresearch. The transferable artifact is the ordering rule — each stop answers the question the previous one leaves open — and the fact that each stop has an unambiguous “it works” signal. Key caveats: nanoGPT's README is now deprecated in favour of nanochat, so read four and run six; the cost figures are the most perishable claim here; and the path stops short of post-training, serving economics, evaluation design and anything about production.

  5. 2026-11-20R204RAG chunk size is the last knob: measure, fix boundaries, restore contextLoosely relevant results come from chunks that lost their subject (too small) or mix topics (too large), so changing size only swaps failures. Order: a labelled retrieval eval with recall@k first; structure-aware splitting with 10-20% overlap; contextual notes prepended before embedding (one model call per chunk); match small, send the parent section; tune size last against the eval. Practitioner advice, no new data.
