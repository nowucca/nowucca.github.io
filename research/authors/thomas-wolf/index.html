  1. 2026-11-25R291Guardrail lockout: what a 17,000-action agentic intrusion taught one platform about defending with agentsAn intrusion into a model-and-dataset hosting platform's production infrastructure, disclosed as driven end to end by an autonomous agent system, read alongside the launch post for the security agent the platform built afterwards. The incident is the first-hand, durable part. Entry was the data-processing pipeline: a malicious dataset abused two code-execution paths — a remote-code dataset loader and a template injection in a dataset configuration — to run code on a processing worker, then harvested cloud and cluster credentials and moved laterally into several internal clusters over a weekend. The campaign executed many thousands of actions across a swarm of short-lived sandboxes with self-migrating command-and-control staged on public services. Detection came from LLM-based triage correlating security telemetry out of daily noise, and forensics ran analysis agents over an attacker action log of more than 17,000 events to rebuild the timeline in hours rather than days. The finding to carry is <strong>guardrail lockout</strong>: frontier models behind commercial APIs refused the forensic work, because it means submitting real attack commands, exploit payloads and C2 artifacts, and provider safety filters cannot tell an incident responder from an attacker. The team ran the analysis on an open-weight model on their own infrastructure instead, which also kept credentials inside the perimeter. Their stated lesson is to vet a self-hostable model before an incident: the attacker was bound by no usage policy while the defender was refused precisely for using a governed service. Key caveats: the product half is a vendor claim with no third-party test, false-positive rate, alert volume and running cost unpublished, and a product mixing open and closed models for security analysis inherits the refusal risk at its closed boundary.
