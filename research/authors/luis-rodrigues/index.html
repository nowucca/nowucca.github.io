  1. 2026-11-18R143MCP vs API: an adapter in front of the same endpointsRight on the core claim: an MCP server is an adapter calling the same APIs, and the difference is that MCP tells a model what it can ask for. Corrections: MCP has no central hub (one client per configured server; a gateway is something you add, R071); discovery is `tools/list` on servers the host was configured with; someone still writes the tool schemas and descriptions; MCP paths that skip the API gateway create a second, less governed route to the data (R074); remote servers need OAuth 2.1 (R062). The 2026-07-28 revision is stateless (no initialize, no session id), puts `Mcp-Method`/`Mcp-Name` headers on HTTP POSTs for gateway routing, and makes list results cacheable, so MCP now looks much like an HTTP API with a model-facing description layer. Lesson: treat tool descriptions as a versioned interface, keep MCP tools under the same policy as their routes, and pick MCP only when a model chooses the call at run time.
