  1. 2026-11-23R230sharedGrepMem: keep summarising, but let the agent grep the verbatim logKeep summarising to hold working memory small, but first append every message and tool output verbatim to a plain-text log, and give the agent a regex search tool over it. With an RL-trained 9B model, exact recall far past the context window reaches 95-97% against at most 21% for summarisation or observation masking, and it beats summarisation by 8.8 points on multi-question research sessions. No embeddings, index or extra model. Limits: one model, controlled benchmarks, and the agent needs a keyword to search for.

  2. 2026-11-20R184sharedExperience Rot: agents with memory stop checking changed toolsAfter a silent MCP-style tool change, agents that had done the task before copied their earlier call, even when the tool definition showed the change, and reported success (347 of 348 failures). Complete docs: 88-100% success with no experience vs 26-49% with stale experience; incomplete docs: about 23% stale vs 42% none. Worse with more experience (46% to 26% over 1 to 10 earlier tasks); every memory form affected; version notices and a system-prompt "check the docs" rule didn't help; reading back stored state before reporting raised success to 91%/69%. Hand-written histories hide the problem.

  3. 2026-11-19R157sharedSelf-Disagreement: training models to hold a correct answer under pushbackModels give up correct answers under wrong counter-arguments, and accuracy training, self-reflection, voting and SCoRe don't fix it: holding vs yielding is a separate 'dialectical competence'. The model states an answer, writes the strongest case against it without the reference, rules on it, and is rewarded with RLVR, the same exact-match check scoring the ruling (no second model, reward model or labels). Capitulation falls 25.3 pp (Qwen3-8B) and 36.1 pp (Gemma-2 9B) vs eleven frontier challengers; Gemma 3 12B from 20.2% to 2.6%; first-answer accuracy holds. Limits: checkable answers only, single-round, and acceptance of correct challenges drops too.

  4. 2026-11-18R138RURL: training an open model to use a real robot the way agents use a computerQwen3.8-27B trained with RL alone in simulation, no demonstrations and no harness: observe camera frames, reason, emit the next end-effector pose. LIBERO 1.6% to 74.4% (near GPT-6 Astra), 18 of 30 on an unseen real dual-arm robot, no loss on nine general benchmarks. Recipe lessons: binary reward needs a curriculum of tasks that already give signal, drop all-pass/all-fail groups, correct async rollout lag, keep prefix-cache hits high. Slow: about 4.3 s of reasoning per move.

  5. 2026-11-17R133VHarness: vision as a callable tool for coding agentsVision-as-a-Tool: an external multimodal model exposed over MCP in Claude Code as five atomic actions (transcribe, grep, inspect, align, diff), called on demand to check rendered output against the target. Improved every multimodal coder tested on Image-to-HTML, SVG and 3D (Opus 4.8 DINOv2 0.72 to 0.87 on HTML); text-only GLM-5.2 with a Gemini judge matched the GPT-5.5 baseline (50 cases per task, static targets only). Stop decisions come from the external check.

  6. 2026-11-16R103EvoTrias: separation of powers for agentic program evolutionThree decisions in LLM program evolution, each with one owner over typed contracts and runtime hooks: Structured Governance (controller picks parents across rounds), Open Proposal (a coding agent writes and repairs inside a round), Protected Judgment (private evaluator the agent can't read). Plug-in for Claude Code/OpenCode. Reported: SOTA on maths, systems and algorithm-design tasks; 64% lower token cost from separating governance (post: ~$41 vs ~$115 per run, ahead on 6 of 7 maths tasks); scales to a 680K-line repo; scores transfer.
