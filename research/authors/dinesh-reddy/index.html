  1. 2026-11-12R054Harness engineering: a source-code study of eleven coding agentsReads the source of Claude Code, Codex CLI, Gemini CLI, Mistral Vibe, OpenHands, Aider, Mini-SWE-Agent, Hermes, Pi, OpenCode and OpenClaw (plus the Omnigent meta-harness as contrast) along seven subsystems: loop, LLM integration, tools, memory/context, safety, orchestration, extensibility; 13 observations, 29 patterns, 18 recommendations. Across ~4M lines no harness imports a general agent framework (Gemini CLI skips Google's own) and none uses embeddings to find code: ripgrep, glob, tree-sitter and Markdown context files instead. Mini-SWE-Agent's ~100-line loop scores in the same SWE-bench range as systems 1,000x larger; loop size predicts production readiness (safety, recovery, extensibility), not score. Skills 9/11 vs MCP 8/11 (Pi rejects MCP, OpenCode reads ~/.claude/skills); ACP in 6, newly used for one harness to host another (OpenHands runs Claude Code, Codex or Gemini CLI); two large systems have no OS sandbox. A 90-day diff shows imitation (Codex took Claude Code's hooks and plan mode) and rules moving from prompts into config; harnesses now ship as SDKs, the new framework layer. Recommendations: start with a while loop and bash, on-demand tools past ~15, no code RAG unless it beats ripgrep plus tree-sitter on a held-out eval, PLAN/DEFAULT/YOLO modes, OS sandbox plus policy-as-code, single-agent by default, ship ACP, skills before MCP, stuck-loop caps; ends with a 90-line Python harness. Caveats: static reading only, qualitative scoring, Claude Code analysed from an unofficial March 2026 snapshot, no head-to-head runs; comments add that grep edits break semantic refactors and agents drift back to grep even with LSP tools.
