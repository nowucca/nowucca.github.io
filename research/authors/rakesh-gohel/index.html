  1. 2026-11-12R058AI-native SDLC: Anthropic's playbook vs AWS AI-DLCFaster build moves the bottleneck to plan, review and deploy, so redesign the lifecycle. The playbook: six non-linear stages of "plays", each committing an artifact the next reads (`intent.md`, `spec.md`, `plan.md`, diff and tests, PR findings, incident record); an accepted artifact fires the next stage and the commit chain is the audit trail. Useful specifics: a leading and lagging metric per play read from git and PR metadata; skills are advisory, hooks and managed settings deterministic; `CLAUDE.md`, skills and hooks regression-tested by a CI eval suite, every incident becomes an eval; failing test first, then a hook blocks test edits during the fix; the writing agent cannot approve; Maintain closes the loop with deterministic sigma bands (log, diagnose read-only, propose via PR or pre-approved runbook) that write a new `intent.md`. AI-DLC is the engine (adaptive depth), the playbook the operating model. Weak spots: vendor-shaped, no outcome data, four Markdown files per change can drift, rationale stays per change, no rule for when a small fix skips intent and spec.
