  1. 2026-11-13R068Plan on the expensive model, hand off to the cheap one: Hassid's Fable-to-Opus briefPlan the whole job on Fable 5.2, then hand execution to Opus 5.5 in a new chat via a written brief, because caches are model-scoped (switching mid-chat re-reads the history cold) and the second model cannot see the first one's thinking. The handoff template: goal with "done when" checks, next step, decisions with reasons and rejected options, facts, done, ask-me-first approvals, open items, checklist, and executor rules (read every relevant file first, keep going instead of offering to continue, don't reopen decisions, end with a recap). Context compaction by hand, with a schema. Caveats: lossy by design, executor improvises on unplanned questions, "keep going" raises the cost of wrong turns, newsletter misreads the Remote Labor Index as head-to-head wins over humans.

  2. 2026-11-12R036Ruben Hassid's Claude 101, checked17 consumer tips, filed as harness advice. Best of them are context hygiene: edit the prompt before a bad answer instead of arguing with it, "Done means: ..." plus the only reason to stop, don't steer the answer, ask for 20 options with the last two under 10% likely, and hand off stale chats with a 10-line summary. Memory: keep it on but short, with a KEEP / FIX / DELETE clean-up prompt that took his memory from 105 facts to 26; one Project per client with account memory off. Its "28% better" is real Anthropic data (Opus 5.5 0.655 to 0.838 on CL-Bench 1.0) but measures an agent's self-maintained memory folder with grader feedback, not the chat Memory toggle. The same post supports "keep it short" (Fable 5's nine files beat Sonnet 3.7's 413) and gives a better reason to empty the instructions box: for strong models, fixed rules on how to use memory cut its gain. Reverses R004's memory wipe; still no before/after measurement.

  3. 2026-11-09R018Ruben Hassid's six levels of Claude, checkedA consumer setup guide in six levels. Two claims hold against Anthropic's own pages: thumbs feedback stores the whole conversation for up to 5 years and may train models, and an owner turning org memory off permanently deletes every member's memory. Switching models mid-chat costs a cold cache, not a "re-read". Takeaways: pin model and effort per conversation, write a feedback-button policy, put the org memory toggle under change control, version config instead of wiping it.
