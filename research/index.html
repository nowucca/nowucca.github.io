1.2Self-improvement and learning loops

  1. 2026-11-11R024InfraRSI: contract-locked agents for training-throughput tuningA self-improving agent harness that speeds up distributed LLM training by searching launch settings and source patches together. The contribution is the verifier: before any edit, `init` locks a task contract (tokens per update, loss tolerance, allowed precisions) and hashes frozen files (data, loss, timers); `doctor` calibrates per-cluster timing noise; five invariant layers (execution, workload, schedule, numerical, timing) and back-to-back re-runs gate promotion, else the delivered speedup is 1.00×. Search keeps global time and censored peak-memory models over all trials (OOMs included) and a cross-hardware experience bank. Four dense and MoE workloads on 8 to 16 H100/H200: 1.83× geomean, mean MFU 17.4% to 30.0%, up to 2.75×; beats RE-Bench's scaffold (1.37×). Offline re-verification rejected 33% of 1,212 runs, and the LLM's own speedup predictions correlated negatively with measurements. Caveats: throughput only, some hacks caught only by human source review, four workloads, no replication.
    self-improving-agentstest-oraclesagent-harnessevalsbenchmarksml-infrastructure
  2. 2026-11-12R063No Second Run: recursive self-improvement applied to a frontier pre-training runClaims the first detailed account of RSI over a whole from-scratch pre-training run: the unrepeatable run is decomposed into smaller loops that can close (proxy runs, ablations, checkpoint evals). Result: 801-30B-A3B-Base MoE, 11.8T tokens, three months, new team; beats Qwen3-30B-A3B and Nemotron-3.5-Lightning, trails Qwen3.5-35B-A3B; with 6B-token SFT only, best average on four agentic benchmarks. Base model and SFT data released. Caveats: proxy validity, no no-RSI counterfactual in abstract, benchmark choice.
    self-improving-agentsmodel-releases
  3. 2026-11-13R066TRUST: a statistical acceptance gate for self-improving agent harnessesGreedy gates (keep a harness update if validation score rises) are fooled by sample noise and validation reuse: 45.59% of accepted updates were worse. TRUST defines a false evolution rate (share of accepted updates causing unacceptable loss) and controls it under a budget across the whole run, FDR-style, using a noninferiority test, overlap correction for reused eval data, e-values, and per-round error-budget allocation guided by an LLM reading the loop history. Proves the FER bound and a lower bound on final gain. HotpotQA, DROP, APPS with DeepSeek-V4-Flash and Qwen-3.8-Flash: bad acceptances 2.78%, higher final scores than conservative statistical gates. Caveats: more eval samples per decision, margin is a policy choice, short-horizon benchmarks, LLM inside the gate.
    self-improving-agentsevalsagent-reliabilitytest-oracles
  4. 2026-11-13R069Actor, judge or teacher: decision models are better critics than agentsDecision models (typed outputs, a probability per option) tested as actor, judge and RL teacher on ALFWorld and WebShop. As actors, all six models (three decision models, three general LLMs) chase an easier subgoal before the prerequisite one; as judges with the full trajectory, the same models credit the skipped steps. "Did this action help?" separates useful from useless actions; "will the task succeed?" does not. As the GRPO teacher, JEV lifts a Qwen2.5-1.5B policy from 72.8% to 82.9% (ALFWorld) and 56.8% to 71.4% (WebShop). Hindsight judging beats acting; a weak actor can be a good critic. Caveats: two text environments, one teacher, small policy.

2.2Consistency and storage tradeoffs

  1. 2026-11-12R046Hardwood: a remote file reader is really a schedulerReading Parquet from S3, the hard part is not decoding but deciding what to fetch and decode next: tens of ms per request, footer at the end, pages gated on bytes plus dictionary plus batch position, sometimes no page index. Goal: run at the slowest resource's speed, never slower due to scheduling. Caveats: author's design note, no scheduler benchmarks yet, fairness and request coalescing not detailed.

  1. 2026-11-12R035Long-horizon agents and durable executionAn agent that runs for weeks is a distributed system: a durable execution runtime (Temporal and Cloudflare Workflows built in full; Restate, Inngest, DBOS named) logs each external call's input and output before the next runs, so a crash replays recorded steps and runs the first unrecorded one for real; waits are logged timers that hold no compute.
