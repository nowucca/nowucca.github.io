1.2Self-improvement and learning loops

  1. 2026-11-11R024InfraRSI: contract-locked agents for training-throughput tuningA self-improving agent harness that speeds up distributed LLM training by searching launch settings and source patches together. The contribution is the verifier: before any edit, `init` locks a task contract (tokens per update, loss tolerance, allowed precisions) and hashes frozen files (data, loss, timers); `doctor` calibrates per-cluster timing noise; five invariant layers (execution, workload, schedule, numerical, timing) and back-to-back re-runs gate promotion, else the delivered speedup is 1.00×. Search keeps global time and censored peak-memory models over all trials (OOMs included) and a cross-hardware experience bank. Four dense and MoE workloads on 8 to 16 H100/H200: 1.83× geomean, mean MFU 17.4% to 30.0%, up to 2.75×; beats RE-Bench's scaffold (1.37×). Offline re-verification rejected 33% of 1,212 runs, and the LLM's own speedup predictions correlated negatively with measurements. Caveats: throughput only, some hacks caught only by human source review, four workloads, no replication.

1.5Context economics and caching

  1. 2026-11-11R026HybridAgent: agents that think in latent space and act in textInside one generation the agent switches between text and latent steps, where a small residual adapter (HybridLink, about 10M parameters at 4B) feeds the hidden state back as the next input with no decoding; tool calls and answers stay in text, and the KV cache carries text, latents and tool results across turns. Trained from Qwen3-Base (4B to 14B) by hybrid SFT with self-conditioning, then RL whose policy factorizes over text positions with exact latent replay. Versus matched text agents: 35.5% to 54.7% fewer tokens, 1.8× to 2.6× faster, about 10% more accurate after RL; 14B scores 52.4 on GAIA vs 43.7 for same-backbone ARPO. Latents read back as approximate pseudo-text and visible-trace monitoring holds up. Caveats: needs open weights and a custom serving stack, the KV cache becomes the only copy of session state, and pseudo-text approximates the computation.

  2. 2026-11-11R032Strands Decider: a decision model replaces an LLM for ticket labelingA decision model is an LLM torso with the LM head replaced by a small pointer head: it cannot write, it returns a probability per offered option plus a calibrated confidence, in one pass (about 115 ms on an RTX 3090, 4,096-token window). Labels rewritten as one-line criteria plus "none"; confidence thresholds tuned; a three-way BEDROCK/DUAL/DECIDER switch judged every disagreement on live traffic; JSON key order moved probabilities by up to 0.19. Caveats: vendor source, no published accuracy numbers, no cheap-generative baseline, fits only closed choices from a stable catalog.

2.2Consistency and storage tradeoffs

  1. 2026-11-12R046Hardwood: a remote file reader is really a schedulerReading Parquet from S3, the hard part is not decoding but deciding what to fetch and decode next: tens of ms per request, footer at the end, pages gated on bytes plus dictionary plus batch position, sometimes no page index. Every step is a job keyed by the first row it serves (lowest first); IO jobs on Java 21 virtual threads, CPU decode on a sized pool or the caller's thread; separate read-ahead bounds for fetched bytes and decoded values; the consumer's next need always runs (progress guarantee); zero-copy decode with reference-tracked buffers. Goal: run at the slowest resource's speed, never slower due to scheduling. Caveats: author's design note, no scheduler benchmarks yet, fairness and request coalescing not detailed.

  2. 2026-11-11R030OpenShell: kernel-enforced sandboxes and verified policy for AI agentsA runtime for agent fleets: a gateway control plane, and per sandbox a split across a trust boundary, with the sandbox side owning the agent's processes and intercepting TCP and DNS (Landlock, seccomp user notification, no capabilities) and a trusted supervisor deciding every request, resolving DNS and injecting credentials only for approved endpoints (agents see placeholders). 2.5Model supply chain and weight integrity

  1. 2026-11-11R033Lazarus: backdooring AI agents by editing a few dormant neuronsRewiring fewer than ten rarely-firing neurons in the final feed-forward block, in closed form and with inference-only compute, makes an open-weight model emit a shell payload (one neuron per token) when a trigger string appears anywhere in context, while passing standard evals. Nemotron-Terminal-8B: 7 of 12,000+ neurons, fitted on 23 trajectories, fire on at least 98.8% of held-out trigger runs and never on benign ones; Qwen 3.6-27B and Gemma-4-31B-IT equally vulnerable. Detectable: agent-built auditors with no reference model flag 91.4% of edited checkpoints at 9.7% FP. Defenses: diff every checkpoint against its declared base, frontier agents as weight auditors, publisher-only sourcing with hashes and a private registry, trigger red-teaming, and containment (least privilege, sandboxed execution, egress controls). Caveats: no audit proves safety, internal models equally exposed via write access, vendor product framing, no observed exploitation.

  1. 2026-11-12R038AlphaProof Code: agents formally verify Signal's protocol implementationGemini 4 Carbon agents wrote about 6.5M lines of Lean proving PQXDH plus Triple Ratchet security (forward secrecy, authentication, post-compromise security, handshake secrecy) against the stock-rustc AArch64 binary of unmodified libsignal, in symbolic and computational models; five people, four weeks, versus about twenty person-years for seL4.   2. 2026-11-12R042Routing a Lean prover's compute on checker signalsA control plane decides after each pair of attempts whether to keep trying a lemma breakdown, using quality minus lambda times cost; quality is a logistic regression on proof similarity, Lean error diversity (strongest feature) and attempt count. 28.9% less compute at equal solve rate, or +7.9% solve rate at equal compute, on a 43-problem PutnamBench test slice; an oracle router would save 62 to 67%. 3.4Test oracles for agent-written code

  1. 2026-11-11R020The model proposes, the harness enforcesLLM conclusions are non-monotonic: reordering, reframing or a long context can overturn an answer nothing contradicted, and the model keeps no ledger of which conclusion rests on which fact, unlike designed belief-revision systems. So guarantees must come from the deterministic harness, defined as whatever you would still trust if the model were trying to fool you. Applied to tests: the runner and property- or reference-checked generated inputs are harness; assertions written by the implementing agent are not ("a mirror with a green light on it"); spec-derived tests need human sign-off; mutation testing checks a test can fail. Cites a reported Codex CLI incident (#59060) where a reboot request wrecked a server. Essay, not study: the ordering experiment is anecdotal, "non-monotonic" is used loosely, and a second agent on the same model and spec adds less independence than it seems.

6.5Long-running agents and durable execution

  1. 2026-11-12R035Long-horizon agents and durable executionAn agent that runs for weeks is a distributed system: a durable execution runtime (Temporal and Cloudflare Workflows built in full; Restate, Inngest, DBOS named) logs each external call's input and output before the next runs, so a crash replays recorded steps and runs the first unrecorded one for real; waits are logged timers that hold no compute. Worked example: a purchasing agent with one entity workflow per SKU starting a child workflow per replenishment (quotes, PO draft, manager approval wait, order, 7-day supplier wait). The runtime covers four generic failures (waits, failed calls, retries via idempotency key, concurrency); the harness owns five: outcomes the agent never saw (treat timeouts as unknown, compensate with cancel_order), stale facts (re-check price in code before commit), code changing under running work (pin rules_version, Parallel Change), unbounded history (continue_as_new, curated model memory), and untrusted text (tools gated by state; only the manager's signal approves). "Durable is not the same as correct." Caveats: Temporal and Cloudflare behaved differently on a mid-wait rule change; cold replay about 2 s vs under 0.1 s; one Python example; security out of scope.
