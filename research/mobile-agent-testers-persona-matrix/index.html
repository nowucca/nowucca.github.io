What it is

A GitHub Actions template that runs many exploratory testers against a mobile app in parallel, with no test scripts. Each job boots one iOS Simulator or Android emulator configured as a persona and gives it to a Claude Code agent. A persona fixes the device model, OS, font scale, dark mode, language and locale, for example an iPhone SE in Swedish at the largest text size, a Pixel 7 at 200%, an iPad in German, or Arabic right to left. The agent uses the app like a new user, or follows a brief, and files a bug report with numbered screenshots. It supports Flutter, React Native, Expo, native Kotlin and Swift, Kotlin Multiplatform, Capacitor and .NET MAUI.

Architecture

  • One workflow builds the app once, then fans out one job per persona. Free runners on public repos allow about 20 concurrent jobs, 5 of them on macOS.

  • Three tools per agent: read the screen (with tap coordinates), perform gestures, type. The action budget is about 30 per run, and a brief can raise it.

  • Built-in accessibility probe on every screen: controls with no accessible name, and touch targets under 48 dp on Android or 44 pt on iOS. The agent confirms each hit against the screenshot.

  • Isolation: analytics are blocked inside the virtual phones, so test traffic never reaches real metrics.

  • Encrypted results: public-repo logs are public, so reports are encrypted with the user's key pair and decrypted locally.

  • Local summary: a model groups reports describing the same bug and shows which personas hit it.

  • Modes: explore like a new user (the default), run one feature end to end from a brief, reproduce a reported bug on every phone (yes, no or unclear), write an improvement report, or compare two builds with the same personas.

Cost is roughly $0.15 to $0.55 per phone. Of LocalSend's 46 bugs, 34 were not about text size or accessibility: they were broken flows, silent failures, missing translations and tablet layouts.

Why it matters

The configuration matrix (device × locale × font scale × direction × theme) is where mobile bugs hide and where scripted UI tests are most expensive to maintain. Turning each matrix cell into an autonomous exploratory tester makes broad coverage cheap. The finding that most bugs showed up on a single configuration argues for breadth over depth.

Tradeoffs

  • Exploration, not regression. Agents find new problems but give no deterministic pass/fail. Keep scripted tests for must-not-break flows.

  • Findings are only as good as screenshot reading. Cheaper models cut cost but miss or invent issues. Human triage is still needed.

  • Free runners assume open source. Closed-source apps need a private repo with paid minutes, or a self-hosted Mac.

  • Usage limits. On subscription plans, 20 parallel agents can exhaust a 5-hour quota in about 15 minutes, so the project recommends batches of 6 to 10.

Failure modes

  1. False positives from misread screenshots or animation timing.

  2. Duplicate reports that model-based grouping merges wrongly, or fails to merge.

  3. Non-reproducible paths: an agent's exploration route is hard to replay exactly.

  4. Secrets exposure if encryption or token scoping is misconfigured on a public repo. The source-repo token should be read-only.

  5. Budget truncation: about 30 actions may stop before deep flows.

Review checklist

  • Which persona matrix matches the real user base (top devices, locales, font scales, RTL)?

  • Is every agent finding triaged and either turned into a scripted regression test or closed?

  • Are results encrypted and tokens read-only on public runners?

  • Is analytics isolation verified, so test sessions don't pollute product metrics?

  • Is per-run cost tracked against bugs found?

  • Is version comparison used before releases, with the same personas on both builds?
