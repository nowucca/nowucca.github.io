What shipped

  • llama.cpp v1.0.0 (libllama) and ggml v1.0.0 (libggml), the C/C++ inference library and the tensor library under it, about three and a half years after the project started.

  • Llama desktop apps for macOS and Windows from the llama.cpp team and Hugging Face, so people can run local models in a few clicks.

This is a stability release more than a feature release.

The versioning promise

From 1.0 on, both libraries follow semantic versioning on their public C headers in include/:

ChangeBump
Breaking change to the public C APIMajor
Backward-compatible feature, backend update, model support or API additionMinor
Bug fix with no API changePatch

API and ABI breaks now show up as major-version bumps. That matters because many downstream apps embed llama.cpp, and until now they tracked a fast-moving API by commit.

Distribution and coverage

  • Packages through pre-release artifacts (Linux, macOS, Windows, Android, iOS), Docker, Debian, Homebrew, conda-forge, MacPorts, Winget and an XCFramework for Apple platforms.

  • More than 150 model architecture variants and the mainstream speculative-decoding methods. Backends are dynamic libraries that can be loaded at runtime.

  • CI runs on Hugging Face Buckets and Jobs, with self-hosted runners donated by NVIDIA, AMD, Qualcomm, Arm, IBM and Intel.

A note on AI in the project's own development

The maintainers say they use LLMs in development "thoughtfully", but that keeping a high-quality codebase, staying in control of the architecture and understanding the implementation stay their top priorities, and they are investing in CI to keep up with the faster pace.

Why it matters

  • Local inference is now a dependency you can pin. For anyone embedding a local model (offline agents, private data, edge devices), a stable C API with semver makes upgrades a normal dependency bump.

  • The desktop apps compete with Ollama and LM Studio for the "run a model on my laptop" user, from the team that owns the engine underneath most of them.

Caveats

  • The post has no performance numbers or changelog of what changed in 1.0 itself.

  • Semver covers the public C headers only. Model-file formats, server flags and the HTTP server's behavior are not stated to be covered.
