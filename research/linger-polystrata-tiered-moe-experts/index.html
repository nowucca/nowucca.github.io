Linger and PolyStrata: a local personal agent on MoE experts tiered across GPU, RAM and SSD

What it is

Two layers. PolyStrata is a MoE inference engine for consumer PCs; Linger is a personal agent on top of it that connects mail, chat, calendar and meetings, builds a local wiki memory, proposes actions and asks before sending. Everything runs on the user's machine, so there is no per-token bill.

The inference idea: expert tiering

A mixture-of-experts model routes each token to a few experts, so most weights sit idle at any moment. PolyStrata exploits that by placing experts by how often they are used:

  • frequently used experts stay in GPU memory;

  • occasionally used ones wait in system RAM;

  • rarely used ones stay on SSD;

  • an expert in RAM that keeps being picked is promoted to the GPU, and one picked from SSD is read into RAM.

The headline claim is a 125B MoE (Qwen3.8-Flash-Next, a 39 GB 2-bit file) running at about 45 tokens/s on a 12 GB RTX 3060 with 64 GB of RAM, where the GPU-only baseline would need more VRAM than any consumer card has. Models with mostly non-attention or short-window layers keep long contexts cheap (for example, a 128K context costing about 2 GB more VRAM than 32K).

Model Autopilot

The installer reads GPU, memory and bandwidth, keeps only models that fit with at least a 64K context, picks the most capable then the fastest, and counts the install as done only after the model answers a real question. The recommendation table comes from a lab sweep of 49 models, two engines, 1-bit to 8-bit quantizations and 64K to 256K contexts.

The agent: memory and nightly self-tuning

  • Wiki memory. Each night, mail, chats and meetings are filed into wiki pages that every agent can search.

  • Proactive messages with approval. The agent watches inbox, calendar and Slack and messages the user only when something needs them; outbound actions such as sending email wait for approval.

  • Rule learning without retraining. A nightly "Dreaming" pass reads how the agent's own messages landed and rewrites a short list of decision rules. Pushing back on the same kind of message twice becomes a rule; an explicit instruction becomes a rule after one pass.

How to read the numbers

  • Many decode speeds were measured on a simulated tier: a larger card held to a smaller memory budget, or a larger Mac standing in for a smaller one. The README says real machines of that tier can be slower.

  • Some figures carry caveats in the footnotes (one headline number was not reproduced under the stated conditions).

  • First-token latency can be minutes on the tightest tiers (about 3 minutes in one 12 GB configuration).

  • The "matches Claude Opus / Sonnet" comparisons come from a third-party aggregate score where within-3-points counts as equal. Treat them as marketing-grade, not as task-level parity.

  • Most PolyStrata models are labelled experimental and were run on one or two machines.

Tradeoffs

  • RAM and SSD bandwidth become the bottleneck whenever routing hits cold experts; prompts that shift topics can thrash the tiers.

  • Privacy vs. capability. Local inference keeps data on the device, but a heavily quantized model on a small card is not the model the comparisons suggest.

  • A custom license, not plain Apache 2.0, so check the extra conditions before building on it.

Failure modes to watch

  • Self-rewritten rules drift. A nightly pass that edits its own decision rules from implicit feedback can learn the wrong lesson from a busy week; the rule list needs to be inspectable and reversible.

  • Ingesting the inbox makes prompt injection through incoming mail a first-class risk for an agent that can also act.

  • Simulated benchmarks overstate what a real card of that size delivers.

Review checklist

  • Benchmark on your own hardware tier, not a simulated one, and record time to first token.

  • Measure decode speed on topic-shifting prompts, not only short chats.

  • Inspect and version the learned rule list; test rollback.

  • Treat ingested mail and chat as untrusted input; confirm every outbound action needs approval.

  • Read the license conditions.
